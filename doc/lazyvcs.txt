INTRODUCTION                                                   *lazyvcs-intro*

lazyvcs.nvim provides native VCS workflows:

- SVN gutter signs, hunk navigation, blame, line log, and file picker
- an editable live diff view for the current Git/SVN file
- a standalone source-control sidebar for nested Git/SVN working copies

The live diff shows the read-only base on the left and your editable file on
the right. Git compares against the index. SVN uses BASE with
`svn cat -r BASE path`. Nonignored Git untracked files and SVN additions
without history use an empty base. Copied and moved SVN files retain their
BASE history. See |lazyvcs-inline-signs| for Git attribute handling.

Git subprocesses always strip GIT_INDEX_FILE, GIT_OBJECT_DIRECTORY,
GIT_ALTERNATE_OBJECT_DIRECTORIES, GIT_COMMON_DIR, GIT_NAMESPACE, GIT_PREFIX,
GIT_SHALLOW_FILE, GIT_GRAFT_FILE, and GIT_IMPLICIT_WORK_TREE. They keep
GIT_DIR and GIT_WORK_TREE only when both are set and not empty, the command
has a working directory inside that canonical work tree (case-insensitive on
Windows), and no directory from the working directory up to, but not
including, the work tree root contains a .git file or directory. A bare
dotfiles repository therefore works in its work tree, while a repository
nested inside it uses its own .git. The .git check is cached per directory for
up to five seconds, and repository redetection clears the cache.
Relative paired Git selectors resolve against Neovim's working directory.
Pathspec flags are stripped from child environments; literal file commands use
explicit pathspecs so commit hooks retain normal glob behavior. Git optional
locks are disabled by default for background reads. Child diagnostics use
LC_MESSAGES=C while preserving other effective locale categories. Authentication
and ordinary Git configuration remain inherited; Neovim's environment stays
unchanged.

Explicit live-diff, signs, and sidebar refresh commands
redetect repository ownership. BufEnter and BufWritePost also revalidate the
buffer directory asynchronously, at most once per five seconds. Cursor movement
uses cached resolution. Git wins equal-root ties. Git and SVN detection have
separate worker pools so a slow SVN probe does not block Git.

The source-control sidebar is native Neovim UI. Neo-tree is not required.

REQUIREMENTS                                           *lazyvcs-requirements*

- Neovim 0.11 or newer. Windows command-tree ownership requires LuaJIT FFI
  (included in standard Neovim Windows builds).
- `git` for Git repositories.
- `svn` for SVN working copies.
- A Nerd Font is recommended for sidebar icons.

COMMANDS                                                     *lazyvcs-commands*

lazyvcs exposes a single command with subcommand completion. Press <Tab> after
`:LazyVCS ` to list subcommands, and again to list the verbs each one accepts.

                                                                    *:LazyVCS*
:LazyVCS              Toggle the source-control sidebar (the default action).

:LazyVCS sidebar {open, close, toggle, refresh, cancel} [path]
                      Control the source-control sidebar. `open` and `toggle`
                      accept an optional directory to scan. On POSIX, selection
                      follows symlinks before parent traversal. Windows uses
                      native path semantics, resolving `..` textually first.

:LazyVCS diff {open, close, toggle, refresh}
                      Control the live diff view for the current file.
                      Defaults to `toggle`.

:LazyVCS compare {open [base], base, next, prev, refresh, close}
                 {edit, files, width, metadata, help}
                      Review total saved changes. Defaults to `open`.
                      See |lazyvcs-comparison|.

:LazyVCS hunk {next, prev, revert}
                      Move between hunks or revert the hunk under the cursor.
                      Defaults to `next`.

:LazyVCS blame {toggle, split, clear, log, selection}
                      `toggle` switches global inline blame using `blame.mode`,
                      `split` shows full-file blame in a fixed-width split,
                      `clear` disables inline blame, `log` shows the Git/SVN
                      log for the current line, and `selection` reports blame
                      for a range or the cursor line. With a range, such as
                      :'<,'>LazyVCS blame, blame reports the selection. See
                      |lazyvcs-blame-selection|. Defaults to `toggle`.

:LazyVCS signs refresh
                      Reload the VCS base and refresh gutter signs for the
                      current buffer.

:LazyVCS files        Pick individual changed and nonignored untracked files.
                     All seven unresolved Git status pairs show as U/conflicted.
                     SVN property changes are included; clean external markers
                     are excluded.

:LazyVCS preview      Preview the current buffer diff in a floating window.

:LazyVCS revert       Discard saved working-tree changes in the current file,
                      after confirming. Git restores the index version and
                      preserves staged changes. SVN runs svn revert, restoring
                      BASE for ordinary modified versioned files.
                      Refuse paths that cannot be placed in the repository.
                      Git refuses directory replacements and requires an exact
                      index file. External filesystem changes are not atomic
                      with these checks.

:LazyVCS profile {show|clear}
                      Show or clear recent source-control job timings.
                      Defaults to `show`.

:LazyVCS health       Run |:checkhealth| for lazyvcs.

All subcommands work in both Git and SVN working copies; the backend is
detected from the current file. See |lazyvcs-notes| for the base each backend
compares against.

Repository filenames and roots are literal: $NAME text does not expand to an
environment variable when selecting, opening, saving, or reverting a file.
Lua API path options are literal too. Paths typed as :LazyVCS sidebar arguments
expand environment variables and ~ before repository discovery. Use $$ for a
literal dollar. Completion protects every dollar in a literal directory name.
Expansion runs once: $$ becomes $, $NAME expands from the environment, and
undefined names stay unchanged. Environment values are never expanded again.
Backslashes and whitespace keep their existing command argument escaping.
Directory completion hides dot names unless the prefix starts with a dot and
respects 'wildignore'. Ignore-pattern matching follows 'fileignorecase';
prefix matching also honors 'wildignorecase'. On Unix, named home paths (~user/)
expand independently of 'wildignore'. An unresolved home leaves the argument
unchanged.
Windows drive-relative paths (C:) are supported.

TOTAL COMPARISON                                           *lazyvcs-comparison*

:LazyVCS compare prompts for a Git branch/commit or an SVN URL@revision.
Git uses the common ancestor of HEAD and the chosen base. Its net comparison
includes committed, staged, and saved working-tree changes. SVN compares the
chosen repository revision to the saved working copy. Parent comparisons exclude
changes to SVN file externals. Versioned files and directories missing from
disk appear as ! rows. Missing files show a labeled empty side when the pinned
base exists, and missing directories show property previews. Scheduled
deletions remain D rows. Neither includes unsaved buffers. Nonignored untracked
files are included by default. SVN ignore matching follows SVN wildcard rules,
including inherited rules in switched subtrees.
Omitted sparse-checkout files use a read-only INDEX (sparse checkout) snapshot
when Git confirms a stage-zero, regular skip-worktree entry. Present files
still use saved filesystem contents. Sparse snapshots receive the full 1 MiB
content limit. A preview never materializes omitted files.

Snapshots decode each source to UTF-8 before display and hunk navigation. Git
working-tree-encoding applies to saved files; normalized blobs use UTF-8. Other
sources try the encoding of an exactly matching loaded file buffer, then
'fileencodings' if that hint cannot decode the bytes. Preview ignores buffer
'fileformat' and 'fileformats': both sides normalize CRLF to LF, and a lone CR
stays inside its line. Editable Compare reads the base with the real buffer's
newline format and the base's own encoding. Git UTF-16LE-BOM and UTF-16BE-BOM encoding names are
accepted without regard to case. Unsupported, lossy, binary, or oversized
conversions show an unavailable reason that names the preview side. Both raw and
decoded text are limited to 1 MiB per side. Blame retains the original source
bytes. SVN saved-preview blame maps decoded BASE lines onto the captured preview
text, so encoding and CRLF changes preserve unchanged-line attribution.
Encoding-profile changes invalidate cached snapshots and remembered review
positions.

SVN metadata includes properties on added versioned files, even when SVN's summary
reports no property changes. Directory properties compare only the selected path
against the pinned numeric revision, without descendant properties. Property-only
patches also appear through p and :LazyVCS compare metadata. Property patches are
limited to 1 MiB per selected path, including generated headers. If optional
properties are unavailable, metadata shows the reason and the text preview
remains available. Metadata loads independently, so binary or oversized file
content does not prevent property review. Returning to text retries content
loading and shows its unavailable reason if necessary. ]v and [v from a
metadata-only result load text and then jump to the first or last hunk.
Untracked paths show "No metadata or property changes for this path." without
requesting SVN properties.

SVN directory-to-file and file-to-directory replacements appear as one R row.
Each file side shows its content; each directory side names the directory.
Metadata compares the path's pinned and working-copy properties even when
neither summary side reports property changes. The [props] marker appears only
when a summary side reports property changes. Deleted children remain separate
rows. Directory-property candidates are omitted only
when both shallow property reads succeed and their byte values match. Failed
validation retains the row with a property-check warning.

A base choice is remembered per worktree and branch, or per SVN working-copy URL.
Detached Git choices last only for the comparison session. Each refresh pins
Git's merge base or SVN's numeric revision. No Git fetch happens automatically.
Unborn HEAD, missing history, unrelated histories, and multiple merge bases
produce an explanation instead of selecting an arbitrary base.

Press C in source control or choose "Compare against base..." from repository
actions. The selected row determines the repository; ambiguous selections use a
picker. The sidebar mapping returns from Compare to source control. Reopening
reuses the comparison tab, refreshes it, and preserves the selected path.

The review tab owns its sidebar and base snapshots. The right pane edits the
real file and includes unsaved changes. Use :write to save; saving refreshes the
file list without moving the cursor. Edited buffers survive closing Compare.
Narrow windows
stack the preview panes vertically. Single-key actions apply to the file list:
    Enter       Review the selected file; double-click does the same.
    P           Preview without leaving the file list.
    <leader>vf  Return from either preview pane to the file list.
    <leader>ve  Edit at the current review position.
    <leader>v?  Show help from either preview pane.
    ]v, [v      Next/previous hunk; wrap within the current file.
    ]b, [b      Next/previous file; wrap and restore review positions.
    e           Fit the file list width; press again to restore.
    o           Open the real file in the original editing window.
    R           Refresh changes and resolve the base again.
    b           Choose another base.
    p           Show metadata or SVN property changes.
    ?           Show floating help; q or Escape dismisses it.
    q           Close the review and return to the original window.

First activation focuses the saved pane at the first hunk, or the base pane
for a wholly deleted file. Reactivating the displayed file preserves position.
From the file list, ]v starts at the first hunk and [v at the last. Navigation
uses config.keymaps.next_hunk/prev_hunk and respects session_keymaps = false.
File navigation uses keymaps.next_file/prev_file and accepts counts, such as
3]b. From a pane it keeps that side when possible. Added files use the saved
pane; deleted files use the base pane. First visits start at the first hunk.
Revisiting restores both panes' cursor and scroll positions. Binary, oversized,
empty, and property-only paths remain navigable. Files load on demand. Clean
private buffers stay unlisted; editing adds them to the ordinary buffer list.
Compare keeps borrowed buffers loaded while in use and restores their prior
'bufhidden' setting on release. Before a pane releases a real file, and before
Compare closes, Compare turns off the pane's diff mode, scroll binding, and
label, so windows that open the file later start without them. o, <leader>ve,
and picker selections remove the diff mode and label that the editor window
they open copies from the pane, keeping the window's own bindings; a window
with its own diff for the file, such as a user or live diff, keeps it. Closing
Compare leaves other windows in its tab, and a picker preview in a pane,
untouched. A session sourced from the Compare tab keeps the layout it
restores.

Known limits: windows Compare does not open follow Neovim's rules for any diff
window. A split of a pane, or another window in the Compare tab that shows a
pane's file, starts in diff mode with the pane's options; |:diffoff| ends it.
|:diffthis| replaces manual folds, and :diffoff leaves the diff folds as manual
folds, so a reviewed file keeps no manual folds in windows that take the pane's
options, and auto-view autocommands (|:loadview|) save that state. A session
saved during Compare restores pane windows with 'foldmethod' diff. While
Compare shows a file again after ]b or [b, a window in another tab that opens
it without options of its own for it can start in diff mode with the pane's
label. When Compare takes a pane back from a picker preview, the preview's own
diff ends in that pane. Its winbar and scroll and cursor bindings remain.
Reloading keeps the real buffer; deleting it shows a fresh saved snapshot until
you select it again.
Positions last for this session, survive refreshes for the same pinned base,
and reset when the base revision or SVN URL changes. Removed paths are forgotten.
Moving the list cursor and background refreshes preserve focus. Unavailable
text previews stay in the list. Text panes preserve normal Vim motions,
search, macros, marks, and jump history. The base remains read-only. Deleted,
symlink, sparse-index, property-only, binary, oversized, and unsupported text
paths retain snapshot behavior. Compare does not offer hunk revert.
Private working buffers in pane jump history stay loaded until their entries
expire or Compare closes. Native jumps can list their destination buffer.
Set compare.editable = false for an entirely read-only review. A single Lua open
can override it: require("lazyvcs").compare({ editable = false }).
Use :LazyVCS compare metadata to toggle metadata from a pane; width, refresh,
base, edit, files, help, and close are also available as commands.

File and grep pickers, including AstroNvim <leader>ff and <leader>fw, can open
files from any Compare window. Selections open actual editable files in the
original editor and preserve search positions, including while a preview loads.
Selecting the already displayed real working file jumps within its editable
pane, using the picker's normal behavior.
Compare keeps its current file.
A split is created when needed to preserve unsaved buffers or winfixbuf.
Editing from a text pane maps the review position through saved and unsaved
changes. Above 1 MiB of editing contents, it clamps the position instead.
Explicit split or tab picker actions keep their usual behavior. Pickers may
add the files you select to your ordinary buffer list.

File rows show the filename before the directory. The > marker identifies the
previewed file independently of the cursor. Auto-fit measures file rows, caps
width growth at half the terminal, and reserves 45 columns for each horizontal
preview when space permits. Compare chooses a feasible arrangement before opening
panes, respecting winminwidth and winminheight. Terminal resizing can stack
previews. Failed construction removes its partial tab and scratch buffers.
Manual width survives tab changes.

LazyVcsCompareTitle, Base, Path, Hint, Add, Change, Delete, Conflict, Current, and
Property are highlight groups with the LazyVcsCompare prefix. They default to
standard theme groups and can be overridden with nvim_set_hl().

Git line totals cover paths with available numeric statistics. Binary,
untracked, recreated, and SVN paths may have no line counts; the header reports
that number separately. Preview content is loaded on demand, capped at 1 MiB.
Binary and oversized paths remain listed. SVN property changes have a property
patch preview for directory/property-only entries.

Lua API: >lua
    require("lazyvcs").compare({
      path = "/path/to/worktree", -- optional; defaults to current file/cwd
      base = "main",            -- optional; prompts or uses remembered base
      include_untracked = true,
    })
    require("lazyvcs").compare_refresh()
    require("lazyvcs").compare_close()
    require("lazyvcs").compare_next(3) -- count defaults to 1
    require("lazyvcs").compare_prev()
    require("lazyvcs").compare_action("files") -- also edit, width, metadata,
                                              -- help, base, refresh, close
    require("lazyvcs").blame_selection(3, 12) -- inclusive line numbers
<
compare_next/compare_prev return false outside Compare's sidebar and panes.
Their optional count must be a positive integer. :LazyVCS compare next/prev
advance one file, including when session mappings are disabled.
compare_action returns false outside a comparison tab and rejects unknown names.

Blame and signs skip buffers whose saved or in-memory size exceeds
`signs.max_file_bytes`. Ignored/untracked files have no automatic blame warning.

MAPPINGS                                                     *lazyvcs-mappings*

Suggested global mappings, as in the |lazyvcs-configuration| install spec:

    <leader>vs   toggle source-control sidebar
    <leader>vo   open live diff
    <leader>vq   close live diff
    <leader>vr   revert current hunk
    <leader>vb   toggle inline blame
    <leader>vc   open or refresh comparison
    <leader>vC   choose comparison base
    ]v           next hunk
    [v           previous hunk

Live diff buffer-local mappings (hunk keys apply in the editable pane):

    q            close the live diff session (keymaps.close)
    <leader>q    close from the left/base diff window
    <leader>vr   revert current hunk
    ]v           next hunk
    [v           previous hunk

From the base pane, use :LazyVCS hunk next/prev/revert or global mappings.

The left/base pane always maps <leader>q as a close alias, in addition to
keymaps.close, because that pane is read-only. It is not configurable;
session_keymaps = false removes it along with the other session mappings.

Pending direct opens stay tied to their original window, buffer, and tab.
Completion preserves focus; a changed destination cancels the open.

Only buffer changes in the session's editable window transfer live diff.
Focus changes to the base pane, other splits, floats, or tabs preserve the
session. Transfers also work with 'nohidden'. Programmatic buffer changes
in the editable window also transfer it, including changes made from another
window or tab, without moving focus.
Transfers reuse the window pair for supported Git/SVN buffers. Unsupported named
files pause the view and show the reason in the base pane. Selecting a supported
file resumes it; :LazyVCS diff refresh retries the paused file. Special or unnamed
buffers close the view. Hunk revert is unavailable while paused or until a pending
transfer finishes. Close and toggle also work while the new base is loading.

Live-diff reverts replace exactly the confirmed hunk using the validated
displayed base. Git uses the index base. SVN uses BASE. These resets use native
buffer replacement even when use_gitsigns is enabled.
Standalone hunk reverts follow the native and large-file rules below.

Splits of the editable window share its diff while the session is active and
leave diff mode when it closes or moves to another buffer, including a move
that is abandoned before it completes.

Source-control sidebar mappings. Unlike the live-diff mappings above, these are
buffer-local and fixed; `config.keymaps` does not reach them.

    q            close the sidebar
    <CR>, l, double-click
                 focus repo, toggle Changes repo rows, run action, or open file
                 diff
    h            collapse node, including Changes repository rows
    C            compare the selected repository against a base
    <Space>      toggle repo visibility; expand/collapse sections
    <Tab>        toggle repo visibility; expand/collapse sections
    R            refresh
    H            toggle clean repos
    e            edit commit message, or toggle auto-fit width
    b            switch Git branch/tag or SVN target
    s            invoke Sync according to sync_button_behavior
    .            always open repo actions (Show Last Error opens full
                 diagnostics)
    c            commit repo
    gm           generate commit message
    ga           stage Git file
    gu           unstage Git file
    gr           revert Git or SVN file
    v            toggle list/tree changes
    S            cycle file sort
    X            cancel this repository's in-flight background jobs
    ?            show sidebar help

With snacks.nvim installed, b opens a VS Code-style Git branch picker with
commands pinned first, current branch marked, and no numeric prefixes.
Picker fallback order is Snacks, fzf-lua, then vim.ui.select, when the required
picker APIs are available.

INLINE SIGNS                                           *lazyvcs-inline-signs*

Git and SVN file buffers get gutter signs automatically. lazyvcs compares the
buffer against the backend base in the background and updates signs after edits:
the index for Git and working-copy BASE for SVN. Nonignored Git untracked
files and SVN additions without history use an empty base. SVN additions show
uncommitted blame; Git untracked files show no inline blame.

Git reads raw index bytes with `git show`. For files with `ident` enabled and no
filter driver, `git cat-file --filters` supplies checkout-form content. Background
base loads never invoke external smudge drivers. Files with a filter driver keep
raw index content. Historical object comparisons also keep raw content.

When `use_gitsigns` is true (the default), lazyvcs delegates Git signs and
hunk navigation when gitsigns.nvim can report this buffer's hunks. Previews
within signs.max_file_bytes compare the whole buffer natively; larger files
can preview a validated gitsigns hunk. Unattached buffers use native fallback.
lazyvcs always renders SVN signs. If gitsigns detaches,
the next edit resumes native signs automatically. Attached gitsigns buffers
keep their normal gutter.

`signs.enabled` controls gutter decorations. Standalone hunk commands and previews
remain available when signs are disabled, without automatic base reads.
Oversized files resume automatic signs after both the buffer and saved file fit
`signs.max_file_bytes`. The exact serialized content size enforces the buffer
limit, including final-newline handling. Clean files at the limit without a final
newline remain supported. Temporarily unavailable bases, including unmerged or
oversized index entries, retain eligibility metadata so signs resume after a
matching LazyVCS mutation.
Unloading a buffer releases its native sign state.
LazyVCS index and SVN BASE mutations invalidate matching bases at process startup
and settlement. Commands wait for settlement, and pending revert confirmations
reject changed base generations. External VCS mutations require
`:LazyVCS signs refresh` to reload a cached base. Within the native size limit,
hunk reverts load a settled native base, check its generation and identity, and
apply exactly the confirmed native hunk without waiting for gitsigns. Above
`signs.max_file_bytes`, LazyVCS applies exactly the confirmed gitsigns-reported
hunk after validating its buffer slice and final-newline state. Pending LazyVCS
base mutations must settle before these large-file reverts, and this buffer must
emit `User GitSignsUpdate` after settlement. LazyVCS requests a gitsigns refresh
when its public API is available. A just-settled mutation also requires this
buffer's next update before large-file reverts can use its hunks. Only that update
clears this requirement. If no update arrives within two seconds, nothing is
reverted and LazyVCS asks you to retry after the signs update. A retry requests
another refresh and waits again. A new base mutation cancels a waiting refresh
with a warning. Buffer unload cancels it silently. A second large-file revert
reports that a command is already pending. Confirmation checks gitsigns hunks and
rejects matching base mutations that begin or settle while open.

Native hunk ranges follow supported algorithm, indent, linematch and whitespace
settings in 'diffopt'. Live-diff and Compare hunk commands refuse icase because
Lua diff cannot reproduce its native Unicode comparisons. Use
:set diffopt-=icase to enable them. Standalone sign commands and diff panes
remain available. Large native comparisons and previews run in a worker thread.
Results from older edits or bases are discarded. Preview completion also
checks the originating window and focus. Editing, leaving the window, or
reloading the base cancels a pending preview. Duplicate pending previews share
one worker. Requests made while a cancelled worker finishes retain the newest
request and start it after completion if its context is still valid. If threaded
diff is unavailable, large native previews report that limitation. Small
comparisons run synchronously. Preview reports insufficient editor space without
allocating a scratch buffer.

Commands:

    :LazyVCS signs refresh   reload the base and refresh signs
    :LazyVCS blame toggle    toggle global inline blame by default
    :LazyVCS blame split     toggle aligned full-file blame audit split
    :LazyVCS blame clear     disable global inline blame
    :LazyVCS blame log       show Git/SVN log for the current line

    :LazyVCS preview         preview the current buffer diff
    :LazyVCS revert          revert the current file
    :LazyVCS files           pick from changed files

Editor blame includes unsaved contents and preserves the buffer's file encoding,
line endings, and BOM. Clean buffers preserve a missing final newline. Modified
nonempty buffers include a final separator when 'fixendofline' is enabled;
otherwise they follow 'endofline'. Binary buffers and lossy conversions are
unsupported. Git applies its normal attributes and clean filters to these bytes.
If Git and the editor use different lines, such as raw UTF-16 or Mac separators,
blame reports an unsupported line format instead of assigning incorrect history.
UTF-16 files normalized by Git's working-tree-encoding attribute are supported.
UCS-2 capture rejects characters above U+FFFF. UTF-16 supports these characters.
Active Git clean filters require bounded full-file blame and ordered source-row
validation, including saved Compare blame. Trailing horizontal whitespace and
ident collapse ($Id: ... $ to $Id$) are supported normalization. Other row rewrites
report an unsupported line format, even when the row count stays unchanged.
Historical blob blame does not inherit the worktree filter policy.
SVN blame rejects UTF-16, UCS-2, UCS-4, and incompatible separator models.
Supported SVN representations require lossless BASE decoding and matching record
counts before mapping saved and unsaved edits. SVN loads committed attribution
and matching text from working-copy BASE, then maps them onto captured contents.
New or changed lines remain uncommitted after saving; unchanged lines keep their
history.

Inline blame refreshes after a buffer is unloaded and reopened or reread with
:edit!. Cursor movement reuses cached attribution between changes. LazyVCS
commits and history changes refresh active inline blame and blame splits after
settlement.

The blame split reloads from unsaved buffer contents after edits. Reloads use
blame.delay_ms and discard results from earlier edits or format changes. The split
aligns its initial viewport and subsequent reloads with the source. While it is
open, the source window has wrapping and folding disabled. Blank virtual rows in
the blame pane mirror source virtual lines and native diff filler, including
diagnostic display changes. Hidden tabs reconcile padding when shown again.
Closing the split restores the source's previous window-local wrap, foldenable,
scrollbind, and cursorbind values, preserving fold definitions.
Ordinary source splits inherit this restoration. Later user overrides and
independent source windows keep their own values.
The split closes when the source window changes buffers, the source is unloaded,
or either window closes. Git line history shows the attributed commit with
commit-wide statistics, including history before a rename. Author names and
messages use UTF-8. Line history uses the current buffer contents and has
no committed revision for newly inserted lines. Pending history is cancelled
when its source changes, closes, or moves its cursor, including during loading.

Hunk commands work in normal Git and SVN buffers too:

    :LazyVCS hunk revert
    :LazyVCS hunk next
    :LazyVCS hunk prev

SOURCE CONTROL                                       *lazyvcs-source-control*

Open the sidebar with:

>
  :LazyVCS
<

Behavior:

- Includes the enclosing working copy and scans for nested Git and SVN repos.
- Supports broad workspace roots such as `~/src`.
- Disambiguates duplicate repo names with relative path labels.
- Shows `Repositories` and `Changes`.
- Hydrates repo status in background jobs. Automatic remote attempts share
  the configured interval across tabs, close/reopen, and aliases of a repository.
  Up to 512 unexpired intervals are retained. When full, new roots use local
  status until an interval expires. Explicit `R` always permits a remote attempt.
- Keeps other repos usable while one repo syncs, updates, commits, or switches.
- Status output beyond 32 MiB shows incomplete counts as unknown and retains
  repository metadata. Stage All and Commit refuse incomplete status. Narrow
  the changes and refresh with R to retry. Cached rows remain visibly marked.
- Keeps cached repo badges visible during refresh. Summary completion preserves
  details loaded while the refresh was pending. SVN incoming rows remain
  available during local detail loading; a successful remote refresh replaces
  them, and a failed remote refresh retains them with an error indicator.
- Supports Git fetch/pull/push/sync and SVN update/switch. Directory externals
  own their status in separately discovered working copies. Parent status
  excludes their contents. An SVN commit that creates no revision keeps its
  commit-message draft.
- Publishes no-upstream Git branches with upstream tracking. Push uses the
  configured upstream remote and destination ref, including local upstreams.
  Configured remote names are literal operands, including leading dashes.
  A different destination branch name is refused unless push.default=upstream
  explicitly allows it. Push confirmations name the source and destination;
  queued mutations recheck both. Pull-only Sync does not apply push policy.
- Keeps repositories with a deleted upstream visible with an `Upstream gone`
  warning. Refresh does not change tracking or republish the branch.
- Uses origin for publishing, or the only configured remote when origin is
  absent.
- Pull and Sync recheck the branch after fetching and when a queued mutation
  starts. A branch change stops the operation with a retry error.
- Unstage preserves working-file edits made after staging a new file. Staged
  rename Unstage and Discard cover both the source and destination paths.
  Discard names both paths in its confirmation and refuses to overwrite an
  untracked or ignored file at the source path. Move that file before retrying.
  Addition Unstage and Discard recheck the index and HEAD when the action starts.
  Changed additions require a refresh and retry. Additions replacing HEAD
  directories remain eligible. Stage refuses directory replacements of files,
  but permits exact stage-zero index gitlinks and ordinary indexed files beneath
  a former HEAD gitlink.
- Intent-to-add Discard refuses because the index has no saved content.
  This includes entries hidden by assume-unchanged or skip-worktree. Restoring
  a staged deletion also refuses an untracked or ignored replacement file.
- Conflict Discard restores HEAD in both the index and working tree. If HEAD
  lacks the path, Discard removes it. The confirmation names this scope.
- Tracked-file Discard checks every restore target, including rename sources
  and destinations. For Git, every proper leading path component is checked
  asynchronously: a .git entry (file, directory, or link), or a gitlink in the
  index or HEAD, refuses Discard of paths inside that repository. Each component
  uses at most one lstat and two Git commands, plus one shared HEAD probe per
  mutation, within the mutation's deadline. HEAD availability is checked once
  per mutation. Only a normal, complete rev-parse exit of 1 means HEAD is unborn;
  unverifiable HEAD checks refuse Discard. Unborn repositories skip HEAD tree
  queries but still check the index. Index queries parse only the first complete
  record. Output overflow keeps stdout's beginning, adds a truncation marker,
  and sets stdout_truncated without stopping the child or changing its exit code.
  Truncation after that record does not imply a gitlink; an unusable first record
  refuses Discard because the ancestor check could not complete.
  Directory obstructions, nested repositories replacing regular files, Windows
  junctions, special files, and unverifiable filesystem errors are refused. In
  SVN working copies on Windows, directory symlinks are refused too, because
  Subversion cannot replace them and its failed revert leaves the working copy
  locked. Ordinary files, other symlinks, and missing files are accepted.
  Submodule directory targets require an exact stage-zero gitlink in the index.
  Staged restores, including rename sources, also require a gitlink or an absent
  path in HEAD. Directory targets are refused when HEAD contains a blob or tree.
  Discard disables submodule recursion even when submodule.recurse is true, so
  pointer restores preserve the populated checkout and its dirty files.
  Symlink targets and their children remain intact.
  Windows link classification passes the literal path through the PowerShell
  child's environment and runs asynchronously. These checks do not make Discard
  atomic against concurrent external filesystem replacements.
- Untracked-file Discard deletes only the selected file or symlink. All directory
  rows, including nested repositories, are refused. Symlink targets remain intact.
- Successful Discard runs Neovim's timestamp check. With 'autoread', unmodified
  buffers reload from disk. Unsaved buffer edits keep Neovim's normal protection.
- Discarding a deleted SVN directory restores its descendants recursively. The
  confirmation names that scope. Unsaved descendant buffers block the action.
  Recorded restore directories and their parents are checked with lstat, without
  following links. Symlink and junction directory obstructions are refused.
  Missing directories can still be restored. These checks share the mutation
  deadline and cannot prevent concurrent filesystem replacements.
  Discarding directory property changes leaves child edits intact.
- Tag checkout and branch creation use the selected full ref, including tags
  whose names start with a dash or match a local branch.
- Branches that share names with tags and real refs ending in /HEAD remain
  selectable. Symbolic remote HEAD aliases are hidden. If ref enumeration exceeds
  the output limit, switching reports an error instead of showing a partial list.
  Closing the sidebar releases pending switch-target loading state.
- SVN switch layout discovery stays below the repository root.
- Generated SVN switch targets preserve literal names, including %, spaces,
  non-ASCII text, and @ characters. Manual Switch URL input accepts SVN URL@PEG
  syntax. End a literal URL containing @
  with another @ to select the URL without a peg revision.
- Opens changed files in the live diff view. Git submodule rows open a
  read-only commit patch for the selected staged or unstaged section. The patch
  includes commit IDs even when submodule objects are unavailable.
- Cancels pending file previews when their sidebar closes, moves to another
  project, or is replaced by another buffer. Delayed opens use their original
  editor window and preserve focus after a tab switch.
- Reopening a displaced sidebar creates a split and preserves the ordinary file.
- Escapes control characters in labels. Actions use raw paths.
- Tree leaves show basenames, with the original path as rename context.
- Sort (`S`) and clean visibility (`H`) update the current rows without
  reloading status or discarding known incoming changes.

Preference reads follow symlinks to regular files, then use the opened file's
type, size, and contents. POSIX opens are nonblocking, so even a FIFO swapped in
after the path check loads defaults without blocking the editor. An atomic
replacement by another editor does not truncate a valid document.

Standalone <Space> waits for 'timeoutlen' so Space-leader mappings can resolve.
`toggle [path]` switches an open sidebar to a different path. With no path, or
an equivalent path, it closes the sidebar. X cancels work for the selected
repository. The sidebar cancel command and API can also stop discovery.

Sidebar status commands allow 32 MiB of stdout and 32 MiB of stderr. Output
beyond that limit retains repository identity and available branch metadata, with
an Incomplete badge and a retry action. Counts show ? and retained groups begin
with Cached. Truncated file records are never treated as complete status.
Stage All is disabled while status is incomplete, and commit preflight refuses
incomplete status. SVN reads branch metadata through a separate local info read.
Commit rereads local status before choosing its scope. Automatic stage-all and
commit refuses unresolved conflicts. Resolve and stage those files explicitly.
Pull and Sync only fast-forward. If branches diverge, merge or rebase explicitly
before retrying. Branch creation uses --no-track, including remote starting refs.
Same-name pushes use an explicit refspec under any push.default policy. Pushing
to a differently named upstream requires explicit push.default=upstream.
Sync checks push policy only when it will push. Behind-only Sync confirms the
fast-forward target without consulting push policy. No-op Sync needs no mutation
confirmation, and diverged branches refuse integration.
Confirmations name the source branch, remote, and destination ref. Push startup
rechecks that destination, the branch, and push.default. Fast-forward startup
rechecks the upstream and captured commit, then merges that immutable commit.

Saving a file refreshes its repository's local rows after a short delay. It
preserves incoming SVN metadata and waits for pending remote reads. R forces
rediscovery and a remote check.

Discard refuses intent-to-add Git files because Git does not store their content.
Unstage or delete those files explicitly. Restoring HEAD also refuses untracked
or ignored files at a restore path, including staged deletions and rename sources.
Move the independent file before retrying. Added, replaced, and deleted SVN
directories discard scheduled descendants recursively. Ordinary directory
property changes retain shallow behavior.

Sidebar highlights use default links that colorschemes can override:
    LazyVcsFile       Normal
    LazyVcsSection    Title
    LazyVcsSecondary  Comment
    LazyVcsDisabled   Comment
    LazyVcsBusy       DiagnosticInfo

Sidebar preferences are stored per project in
`stdpath('state')/lazyvcs/source_control/<sha256(normalized-root)>.json`.
The legacy `lazyvcs/source_control.json` is read when no project file exists.
Saving preference changes migrates only that project and leaves the legacy file unchanged.
Different projects save independently. Concurrent saves of the same project
merge only changed fields. Two changes to the same field use the last completed
write. Visibility changes merge per repository. Unchanged lifecycle saves do not
write preferences. Defaults follow configuration until explicitly overridden;
selection_mode always follows configuration. Existing saved view preferences
remain explicit overrides because older files have no provenance. Remove the
project preference file to reset those overrides. Invalid fields are ignored.

Git and SVN commits read messages from private temporary files, which are deleted
when the commit process exits. Message length does not consume process argument
space. Pasted commit messages retain their subject and body when saved and
reopened.
The input grows to show multiple lines and scrolls through longer messages.
Failed or cancelled commits preserve the draft. Sidebar Git commits store
UTF-8 messages without changing repository configuration.

Refresh restores previously loaded or loading expanded changes and preserves
section and folder expansion. It also restores the selected file unless you
move during loading. Failed local status reads show an error and a retry action.
Enter on "Press <CR> to load changes" loads the changes without collapsing the
repository.
Enter on an expanded repository collapses it while an action or detail load is
running, or after a detail load fails. When no action is running, Enter on a
collapsed repository loads or retries missing details. The error row
retries failed status reads explicitly.
Resumed detail requests show "Loading changes..." until they finish.
Repository actions refresh local rows in sibling sidebars across tabs. Sibling
reconciliation reads local status; it does not request another remote check.
SVN commits, updates, and switches discard shared incoming metadata until the
next remote check. Reverting a file preserves that metadata.

Generated sidebar buffers do not retain undo history.
Sidebar windows disable native folding locally so expanded rows stay visible.
Editor folding is preserved. Manual sidebar resizing survives rendering and
reopening an existing sidebar window. Filenames and metadata reflow after
resizing.

Pressing `e` outside a commit-message row toggles sidebar auto-fit. The width is
capped by `source_control.auto_expand_max_width_ratio`, then restored when `e`
is pressed again.

SELECTED-LINE BLAME                                   *lazyvcs-blame-selection*

Select text and run :LazyVCS blame or :LazyVCS blame selection. Vim supplies the
range, for example :3,12LazyVCS blame. Without a range, "blame selection" uses the
cursor line. Characterwise and blockwise selections include every touched line.
The report shows original line numbers, revision, author, date, and source text.
Press q or Escape to close it. Results describe the selection at request time.

The Lua API blame_selection(first, last) accepts inclusive line numbers. With no
arguments it uses the active visual selection or cursor line. An optional map: >lua
    vim.keymap.set("x", "<leader>vb", "<Plug>(LazyVCSBlameSelection)")
<
Replacing a selection report cancels its request and releases its window.
Further source edits cancel pending editor selections immediately, including
edits to an already modified buffer. Completed reports keep their captured text.
Late results do not change the replacement buffer. Backend failures remain in a
readonly report with separate diagnostic lines until you close it.

Editor blame includes unsaved contents. Compare base panes use the pinned
revision and original rename path. Git saved panes use the captured HEAD and
saved preview bytes, including their original encoding and line endings. SVN
saved panes map working-copy BASE to those contents.
Older Git versions map saved lines to the pinned blob before requesting blame.
For clean filters, whitespace normalization only validates row correspondence.
Actual cleaned rows determine whether saved edits are uncommitted.
Metadata and directory previews have no line attribution. Modern Git normally
requests only the selected range. Representations that may use a different Git
line model require bounded full-file validation. SVN loads file blame once.
Files are limited to 1 MiB and command output is bounded. Changed or closed source buffers invalidate pending results.

Optional integrations are detected at runtime:

    gitsigns.nvim     Git signs, navigation, and large-file hunk previews

    Claude CLI        Commit-message generation with `gm`

Commit messages can be generated from the source-control sidebar with `gm` or

Main options:

    debounce_ms        Delay before live diff refresh.
    diff_highlighting  "syntax" (default) hides LSP semantic overlays in all
                       diff panes. "editor" keeps the editor's colors.
    use_gitsigns       Delegate Git signs, navigation, and large-file previews.
                       Live hunk resets use native buffer replacement.
    set_winbar         Set simple winbar labels during live diff.
    diff_style         Diff presentation; see |lazyvcs-diff-style|.
                       enabled: use subdued filler and directional colors.
                       filler: "auto" or a string of display width one.
                       removed: color old-side-only lines as removed.
    session_keymaps    Add buffer-local live diff and Compare navigation mappings.
    base_window.width  Left/base diff window width. Values <= 1 are a ratio
                       of the combined pane width; values > 1 are columns.
                       Column counts round down after classification.
                       Reapplied on resize. Each pane keeps at least 30 columns
                       when space permits. Sidebars are excluded.
    base_window.collapse_absent
                       Shrink a confirmed absent side to a narrow rail.
                       Default true. See |lazyvcs-absent-rail|.
    base_window.cursor_sync
                       Keep both diff cursors on corresponding lines.
                       Default true.
    base_window.align_wrapped
                       Keep corresponding lines on the same screen row
                       when the panes wrap. "off" (default) leaves
                       Neovim's own binding in charge; "auto" pads the
                       shorter side with virtual rows. See
                       |lazyvcs-wrapped-diffs|.

Live diff keymaps:

    keymaps.close      Close the live diff session. Default "q".
    keymaps.next_hunk  Jump to the next hunk. Default "]v".
    keymaps.prev_hunk  Jump to the previous hunk. Default "[v".
    keymaps.revert_hunk
                       Revert the hunk under the cursor. Default "<leader>vr".

Compare-only file keymaps:

    keymaps.next_file  Next comparison file. Default "]b".
    keymaps.prev_file  Previous comparison file. Default "[b".

Compare pane shortcuts:

    compare.editable   Edit real working files in the right pane. Default true.
                       false keeps both panes as saved-content snapshots.

    compare.collapse_absent
                       Shrink a confirmed absent side to a narrow rail.
                       Default true. See |lazyvcs-absent-rail|.

    compare.keymaps.files  Focus the file list. Default "<leader>vf".
    compare.keymaps.edit   Edit at the review position. Default "<leader>ve".
    compare.keymaps.help   Show help. Default "<leader>v?".

    compare.max_cached_files
                       Maximum cached files, plus current or visible/pending
                       files. Default 32; 0 means unlimited. Must be a
                       nonnegative integer. Snapshots are unlisted and loaded
                       on demand. Eviction drops marks and native jump targets;
                       remembered review positions survive. Refresh keeps
                       cached buffers for the same base; closing releases them.
                       Snapshots displayed elsewhere remain frozen until hidden.

Each key accepts a string, or `false` to leave the key unmapped. Empty strings are
rejected, and binding two of them to the same key is a configuration error.
File/hunk keys cannot replace fixed list actions such as q, b, R, or Enter.
Pane shortcuts cannot duplicate each other or file/hunk keys. Validation expands
Leader, LocalLeader, and terminal key notation. session_keymaps = false disables
Compare navigation and pane shortcuts; sidebar actions and commands still work.

Unknown or removed configuration keys are reported once at startup with
|vim.notify_once()| rather than being ignored silently.

Diff highlighting is window-local. Other views of the same buffer keep their
colors. For inherited window colors, LazyVCS adds semantic-group mappings to
'winhighlight' and removes them on release, preserving mappings you change
while the diff is open. Statuslines and other raw option readers see this overlay
while the window is managed. New splits and floats keep only your mappings.
If a native overlay does not activate on Neovim 0.11, LazyVCS uses an explicitly
activated reusable namespace. Empty mappings restore namespace inheritance on
release. User mapping changes and later external namespace owners are preserved.
On Neovim older than 0.11.7, a released diff window keeps the explicit window
namespace instead of returning to inheritance.
Explicit custom highlight namespaces use a reusable namespace that resolves
links through the source theme; closing restores the previous namespace.
On runtimes with link_global support, LazyVCS keeps a window's source namespace
if any link target resolves differently there than globally, following the full
link chain. Neovim's public API cannot distinguish ordinary and global-only
links. Links to unmodified targets or identical definitions keep the pooled path.
Source-preserving windows retain semantic overlays and their 'winhighlight'.
Use diff_highlighting = "editor" to retain semantic colors in every diff window.

ABSENT FILE RAIL                                         *lazyvcs-absent-rail*

Compare and live diff shrink a confirmed absent side to a narrow rail after
loading a text comparison. Both windows remain in native diff mode. Added files
use a left rail; deleted files use a right rail. Unknown presence, loading,
errors, metadata, properties, binary files, and oversized previews do not
collapse. The current pane never collapses.

The rail has max(3, 'winminwidth') columns, or max(1, 'winminheight') text rows
in stacked Compare. It hides number, sign, fold, and status columns. Layouts
that cannot gain space retain the normal split. The present pane's label
explains the absence, while the rail keeps its short label.

Focus the rail with the mouse or a window movement such as CTRL-W h to expand
it. Compare restores equal panes; live diff restores base_window.width. It
stays expanded across refresh and resize for that file and base. Showing
another file or changing the base resets the choice. Picker previews and
internal window calls do not expand it. Compare's e and :LazyVCS compare width
continue to size the file list.

Set compare.collapse_absent = false or base_window.collapse_absent = false to
keep normal pane sizes with hatched filler. Rail options are restored on
expansion and close. Session saves project the original window options.

DIFF STYLE                                              *lazyvcs-diff-style*

Compare and live diff mark empty regions with a faint diagonal hatch (╱).
These are alignment filler rows, not deleted text. LazyVcsDiffFiller defaults
to NonText and inherits the window background. Old-side-only lines use
LazyVcsDiffRemoved, which copies the theme's DiffDelete colors. New-side-only
lines keep DiffAdd. DiffChange and DiffText keep their theme colors. User-defined
highlight groups and explicit DiffAdd/DiffDelete winhighlight mappings win.
Blame splits are unaffected.

Live window mappings use private LazyVcsOverlayFiller/Removed aliases. Customize
colors through LazyVcsDiffFiller/Removed. The two aliases, LazyVcsSemanticHidden,
and pairs LazyVcsDiffOwner:LazyVcsDiffOwner<digits> are reserved for cleanup;
other mappings, including mappings to the public groups, remain user options.

Set diff_style = { enabled = false } to keep native diff colors and filler.
Set filler = "/" for a plain hatch, or removed = false to keep native DiffAdd
on both sides. The default filler = "auto" respects an existing diff: entry in
the effective 'fillchars'. All changes are window-local and restored when
the pane releases them; changes you make while a view is open are preserved.
For copied diff windows, apply custom options on WinEnter or with vim.schedule
from WinNew. Earlier non-nested WinNew callbacks can run before cleanup of copied
options and suppress the option events needed to preserve equal-value changes.
Your 'diffopt' is respected, including a value without filler or with linematch.
If 'ambiwidth' is double when a view opens, the hatch falls back to /.
Changing 'ambiwidth' to double after opening may raise E835. Choose filler = "/"
before opening to avoid that error.

Labels distinguish confirmed absence from empty content. An added file shows
"No file at <base>" on the old side and "Added (no file at <base>)" on the new
side. A deletion shows "Deleted from worktree" on the old side and "No file in
worktree" on the new side. A confirmed Git intent-to-add shows "Intent to add
(no staged content)". Present zero-byte files append " | Empty", including
empty additions. Unknown presence keeps the existing labels. Compare retains
its path labels and WORKTREE (unsaved) indicator. Live Git compares against the
index, so staged additions have a present base while untracked files do not.
Reused namespaces and ColorScheme refreshes replace copied default definitions
with the current theme colors, preserving the source definitions.
The internal overlay is bounded to 4096 entries and 256 KiB, plus your mappings.
Excess semantic groups retain editor colors if either bound is reached.
Syntax comments, diff backgrounds, diagnostics, signs, and blame remain visible.
LSP clients stay attached. This also prevents inactive-code dimming when a
language server cannot resolve build flags. It does not fix missing build flags.
LazyVCS uses available syntax highlighting without installing parsers.

Native gutter signs options:

    signs.enabled      Enable native Git and SVN gutter decorations.
    signs.debounce_ms  Delay sign refresh after buffer edits.
    signs.sign_priority
                       Sign-column priority, clamped to 1..65535.
    signs.max_file_bytes
                       Skip files exceeding the limit on disk or in memory.
    signs.text         Sign glyphs for add/change/delete/topdelete/changedelete.
                       Each glyph must be empty or printable text occupying
                       one or two display cells. Controls and tabs are rejected.

Git/SVN blame options:

    blame.mode         `inline`, `split`, or `off` for :LazyVCS blame.
    blame.persist      Remember the inline blame toggle across sessions.
    blame.delay_ms     Debounce before inline fetches and split reloads; the
                       overlay then tracks the cursor instantly. When a buffer
                       appears in multiple windows, it follows the active cursor.
                       The annotation is shared by those windows.
    blame.loading_delay_ms
                       Delay before showing slow-load feedback.
    blame.loading_text Muted text shown while slow blame is still loading.
    blame.uncommitted_text
                       Muted text for local/uncommitted blame rows, preserved verbatim.
                       Short, empty, and multibyte labels also work in splits.
    blame.format       Inline format with {author}, {date}, {revision}, and

    blame.max_width    Maximum inline blame text width.
    blame.split_min_width

    blame.split_max_width

Terminal Neovim cannot apply true per-text opacity. lazyvcs uses muted,
theme-aware Comment highlights for blame text. Inline blame stays quiet during
fast loads, shows blame.loading_text for slow Git or SVN calls, and labels
local/uncommitted rows with blame.uncommitted_text. Git untracked files have
no blame history and show no inline annotation.
SVN attribution preserves full author names, including spaces. Copied and moved
files, including directory children, retain their pinned origin history. A
local attribution cache holds at most 32 paths and 16 MiB, keyed by URL, revision
and pristine checksum. Binary or unsupported decoded line models are refused.
Git blame metadata is UTF-8 even when i18n.logOutputEncoding requests another
encoding.

Editor requests use two additional Git workers and one additional SVN worker.
SVN incoming snapshots survive sidebar closure and are shared across tabs.
Successful remote checks replace them, including empty results; failed checks
retain them. SVN mutations invalidate snapshots at startup and settlement.
Retention is bounded to 512 roots and 4 MiB. A throttled open without a retained
snapshot shows unknown remote status (`?`) until the next remote check.

Sidebar cancellation does not cancel editor requests.

Every scheduled command is cancellable and bounded. A mutation that hangs
forever cannot be distinguished from one still in progress, so
mutation_timeout_ms rejects values below 1 ms. Cancel in-flight work with :LazyVCS sidebar
cancel, with `X` in the sidebar, or with
require("lazyvcs").source_control_cancel(). Cancel also stops repository discovery.
Cancelled status reads stay stopped until an explicit refresh or reopen.

Logical cancellation can finish before physical cleanup; the worker stays
occupied until cleanup completes. On POSIX, timeout and cancellation terminate
owned command descendants in separate process groups. Descendants that create
another session or leave the group are outside this cleanup.

On Windows, cancellation of owned commands terminates their helper and tree.
Other commands use taskkill /T /F for timeouts and shutdown termination.
Tree ownership applies to mutation or remote scopes, Git fetch, pull, push,
clone, ls-remote, remote update, and commit, and SVN checkout/co, update/up,
switch/sw, merge, commit/ci, import, and status with -u or --show-updates.
Other cancellations terminate only the direct process, including SVN log,
blame, and URL reads. Their transport helpers exit when the parent's pipes
close, so reads need no tree walk. taskkill requires a live direct process and
falls back to direct termination. Descendants whose parent has already exited
may survive for commands without an owned job. Explicit editor Git restore and
SVN revert cancellation use mutation scope and terminate owned descendants.
Forced cancellation can leave Git locks. LazyVCS reports recovery guidance
immediately on Windows, adds the exact index.lock path when detected, and
never deletes locks automatically.

Neovim exit discards queued work, including mutations that have not started.
Running repository mutations (commit, update, merge, switch, stage, unstage,
revert, push, publish, and delete untracked) are untracked without a termination
signal. Multi-step actions (Pull, Sync, Push, Publish) are preserved only once
they reach their mutating step. This avoids interrupting writes that could leave
an index.lock or a locked SVN working copy. Preserved commands lose their output
pipes at exit. On Windows, commands requiring tree cancellation use a Neovim
Lua helper with a hidden console and a restrictive Windows job. The helper uses
LuaJIT's built-in FFI, inherits standard streams and waits for the command. Only
preserved commands detach from the editor. Explicit cancellation and timeouts
terminate the helper and its owned descendants, including native shell children.
Normal command completion releases the job so intentional background work can
finish independently. Background helpers should close inherited output handles.
An exited command retains its exit result; inherited pipes drain only until the
request deadline, then close without killing intentional background work. Other
scopes retain taskkill fallback.
A hook or helper that writes output afterwards can fail and abort the mutation.
Git aborts cleanly in this case without leaving an index.lock.
Commit message files survive exit in stdpath("cache")/lazyvcs/commit, with a
private directory (0700) and exclusive files (0600) on POSIX. Each file is removed
when its command physically completes while Neovim runs. Logical cancellation
keeps the message until the process exits. Each cached message has an ownership
record with the creating editor's PID and scope before the consuming command's
PID is attached. Both processes share that scope. Boot time is derived from
os.time() minus vim.uv.uptime(). Linux also records the kernel boot ID when
readable and the PID namespace device and inode. Ownership records are synced
before rename.

Setup prunes asynchronously, reading one ownership record at a time. Settlement
or a changed Linux kernel boot ID releases a message. With a Linux boot ID pair,
attached records otherwise require consumer ESRCH in the same PID namespace.
PID-less records wait for settlement or a boot ID change, even in a foreign
namespace. Matching boot IDs take precedence over boot-time estimates.

Without a boot ID pair, attached records require consumer ESRCH where the
namespace matches, or an mtime more than one day (86400 seconds) before the
current boot estimate. Foreign Linux namespaces cannot be probed. PID-less
records use the one-day margin on every platform. A detached consumer can outlive
its editor, so editor exit alone never releases its message. An estimate change
alone never releases a message.

The one-day margin also covers valid legacy PID-less records without an editor
PID. A forward clock step of more than a day can falsely release a message
through that margin. PID reuse delays cleanup; permission failures alone do not
prove exit. A failed deletion after physical exit leaves a settlement receipt
for later cleanup. No additional boot identity source is used.

Messages with missing, unreadable, invalid, token-mismatched, or foreign-platform
ownership records also require an mtime more than one day before the current
boot estimate. Orphaned .owner, .settled, .owner.tmp, and .settled.tmp sidecars
use the same margin and are removed only when their message is gone. Cleanup
errors do not interrupt setup.
If the cache directory cannot be created or protected, that commit uses
vim.fn.tempname() instead. Such commits cannot outlive the editor and are
cancelled at shutdown.
Read-only and background commands (status, diff, blame, log, fetch, AI context,
and discovery) are terminated, including editor requests and commands already
cancelled. Mutation preflights cannot start a mutation during shutdown.
Exit cleanup uses shared deadlines of up to 100 ms after TERM and up to 200 ms
after KILL for reaping. Application callbacks are suppressed during shutdown.
Required resource cleanup still runs. Forceful termination of read-only and
background commands is requested even if the OS cannot reap them within that
budget.

Git terminal prompts are disabled by default with GIT_TERMINAL_PROMPT=0. An
explicit command environment can override that value. SVN commands always use
--non-interactive. Configure credentials before running remote operations.
On POSIX, commands run without a controlling terminal. Terminal passphrase
prompts for signing and interactive SSH host-key or passphrase prompts fail
immediately. GUI pinentry and agents are unaffected.

CopilotChat.nvim requires the main client API with client:ask(opts),
client:models(), and client:get_providers(), plus plenary.async.run and
plenary.curl returning Jobs with shutdown support. Unsupported
versions return a provider error asking you to update CopilotChat.nvim.
Generation sends one literal user message and a fixed system message, with no
inherited selections, resources, tools, or chat history. Diff directives such
as #file: stay literal and cannot attach other files. Only the configured scalar
CopilotChat model and temperature are reused. LazyVCS cancels the request's
transport processes on cancellation or timeout. Cancellation delivers no result;
timeout reports one error. Other CopilotChat requests remain independent.
Successful streams stop their remaining curl process and retain its handle until
libuv reaps it, before delivering the message. CopilotChat curl processes also
share the editor-exit TERM and KILL deadlines. Curl has no descendants, so these
transports use direct signals on every platform, including Windows.

LazyVCS removes request files after the transport exits. Ownership requires a
name returned by os.tmpname() or vim.fn.tempname() during the synchronous
CopilotChat leaf call and that same name passed as a curl file option. Existing
caller files and replaced files are preserved. If CopilotChat changes its
temporary-file API, generation continues but unrecognized files may remain.
Compatibility is tested with CopilotChat client 1e06be9 and Plenary b9fd522.

CLI diff context reaches providers over stdin, or as a private 0600 attachment
that is deleted on completion, so it never appears in process arguments or
task listings. Codex runs with a read-only sandbox and approval disabled.

Sidebar generation shows a Generating label. Replacing a nonempty draft asks
Replace or Keep. Failure notices fit one screen row, and Show Last Error in the
repository actions displays full diagnostics. Invalid UTF-8 context bytes become
ASCII byte escapes before the context limit applies. SVN-generated diff and
status paths are relative to the working copy.

New sidebar generation cancels the previous request for that repository. Submitted
drafts and successful commits invalidate pending results, even when submitted
text is unchanged. Closing the sidebar, changing its path, or cancelling repository
work also cancels its pending generation. Separate sidebar drafts stay independent.
Repository cancellation also stops commit-input generation during privacy
confirmation, context collection, or provider execution. The input keeps its text
and remains open for editing or retrying generation. Closing the input cancels
its request. Late results and replacement confirmations cannot overwrite text
after cancellation.

AI context commands use the repository scheduler and its cancellation and output
limits. Failed context commands stop generation and report the error. Only a
successful empty diff falls back to other changes. SVN status context supports
working-copy paths containing @. Single-command context accepts partial output
and caps that context at max_context_chars in the prompt. The `all` context
rejects truncated command output.

Mutation confirmations enter Normal mode, including after an Insert-mode <C-o>
command, and use a small native popup. Press 1 to confirm, 2 to
confirm and skip more mutation prompts for the current Neovim session, or 3,
q, or <Esc> to cancel. j/k and arrow keys move the selection; <CR> runs the
highlighted choice, including after normal cursor or mouse movement. Confirm is
highlighted by default.

NOTES                                                           *lazyvcs-notes*

- The Neo-tree adapter has been removed. Use |:LazyVCS| or `:LazyVCS sidebar`.
  Sidebar diffs prefer the recorded editor. Otherwise they prefer an ordinary
  non-diff editor in the originating tab. Special plugin buffers, floats,
  preview windows, fixed-buffer windows, Compare panes, and live-diff bases are
  excluded. A user diff window remains eligible when no non-diff editor exists.
  A pending open is cancelled if its captured destination changes.
- With Resession installed, saving an active live diff serializes the editable
  window's pre-session options. The live panes resume after saving. Saves preserve
  affected views. The adapter records and restores only enabled diff-method folds,
  including folds in neighboring user diff windows. Diff folds have one level. Other fold
  methods are never touched. Fold capture failures skip fold restoration for that
  window; mismatched diff ranges are skipped during restoration. Option projection
  still runs. Options changed by the user during the session are preserved.
  Temporary bases and LazyVCS sessions are not restored in a new process.
  No dependency is required.
- Read-only live comparisons close when either owned pane displays another
  buffer. The replacement buffer stays in its window. Editable right panes
  transfer their live diff when you switch to another supported file.
- Git compares live diff buffers against the index.
- SVN compares live diff buffers against working-copy BASE.
- Nonignored Git untracked files and SVN additions without history show an
  empty base. Copied and moved SVN files retain their BASE history.
- Native hunks compare decoded UTF-8 buffer text with the Git index or SVN BASE,
  preserving CRLF, BOMs, supported file encodings, empty files, and final-newline
  changes. Raw and decoded live-diff content is limited to 1 MiB per side; signs
  also honor signs.max_file_bytes. Unsupported or lossy conversions and symlink
  bases are refused. BOMs are recognized only for the effective encoding and byte
  order. BOM-shaped bytes in legacy encodings remain content. Read-only Compare
  symlink previews remain available.
- Hunk commands retain the invoking window, filename, cursor, text, and text
  options while loading or confirming. A changed context cancels the operation.
  Git also revalidates the effective base bytes after attribute conversion.
  Renaming a buffer invalidates its cached base. Delete-only hunks select only
  the displayed sign anchor, including deletions at the start or end of a file.
- Whole-file revert identifies the target pathname in its confirmation and
  cancels when the originating window, buffer, filename, text, or options change.
- Hunk text replacement is undoable, but Neovim undo does not restore changes to
  'endofline' or 'fixendofline'. These options change only when the reverted hunk
  covers EOF; restoring a missing final newline disables 'fixendofline'.
- Pane presentation options stay local. Closing a pane restores its previous
  settings, including an inherited global winbar. Other windows keep their
  defaults, and unrelated diff windows remain active.
- A float showing the same buffer as a diff pane can copy its local bindings,
  as with native :diffthis. Floats showing fresh buffers use inherited defaults.
- To recover an already broken Compare tab, close and reopen it, or run
  :diffoff! followed by :LazyVCS compare refresh. :diffoff! resets the entire
  current tab's diff group, including unrelated diff windows.
- Live diff shows the VCS base (old) on the left and the editable file
  (new) on the right.
                                                        *lazyvcs-wrapped-diffs*
- LazyVCS mirrors the editable window's `wrap`, `linebreak`, and `breakindent`
  settings to the base window. Native diff mode disables wrapping unless
  `followwrap` is present in 'diffopt'. To preserve wrapping:
>
    vim.opt.diffopt:append("followwrap")
<
  LazyVCS does not change 'diffopt'.

  'scrollbind' binds buffer lines. Different wrapped heights can leave matching
  lines on different screen rows. `base_window.align_wrapped = "auto"` pads
  the shorter side with virtual rows. Wrapped changes before the first line
  get no extra padding, so the panes line up once line 1 scrolls out of view.
  It aligns stationary panes, but is off by default because native scroll
  binding cannot see the padding and may drift while scrolling.

  Padding changes no text. It updates after wrapping-option changes and clears
  when both panes stop wrapping or the session closes. It is skipped when
  another window shows the same file, because buffer-local extmarks appear there.

- Inline blame is one global toggle; with `blame.persist` it is saved to
  `stdpath('state')/lazyvcs/state.json` and restored on the next launch.

Compare and session saves: AstroNvim may skip autosaving a Compare tab because
its panes include scratch buffers. Explicit Resession saves while Compare is
open can omit borrowed files or retain Compare window options. Close Compare
before saving a session; live-diff save integration does not cover Compare.
